# Fork review — 2026-10-08

Reviewed the local fork against `origin/master` at `f500d32`, including the pending
FHR export integration and the OTB Hi-C phasing changes. Fixed the following
issues before pushing:

- Untrimmed short reads were dropped before Merqury database preparation.
- Hi-C-only samples could lose their prepared read pair or enter preparation twice.
- HiFi-only samples selected missing ONT QC reads; supplied assemblies without long
  reads were dropped while joining fastplong reports.
- Samplesheet `false` values were replaced by global flags. Missing nf-schema
  values are now recognized separately from explicit false and zero values.
- Duplicate input IDs and collisions with generated haplotype IDs were unchecked.
- Optional hifiasm outputs allowed incomplete phased assemblies to disappear
  silently. Both haplotypes are now required for every phased input sample.
- Dorado used a polished-assembly metadata key that downstream polishing and
  scaffolding did not recognize.
- The Flye scaffold selector referenced an undefined strategy variable; GFA
  publication selectors did not match the actual process aliases.
- The bgzip stub wrote into an output directory it had not created.
- Genomeqc manifest rows for supplied assemblies pointed to unpublished files.
- The FHR container lacked `ps`, which Nextflow requires for task tracing.

## Verification

All of the following passed with Nextflow 26.04.6 and Java 21:

- The full pipeline's `--help` entrypoint and nf-schema plugin initialization.
- Native FHR integration tests from the preceding implementation, plus the full
  Docker FHR integration suite after adding `procps`. These cover actual converter
  validation, matching YAML/FASTA checksums, compressed/plain inputs, preserved
  CRLF bytes, per-sample metadata and haplotype overrides, automatic current dates,
  invalid metadata/IDs and a disabled export scheduling no tasks.
- `tests/review/initialization.py`: actual nf-schema parsing, explicit false
  precedence, CLI phasing inheritance, HiFi QC selection, duplicate IDs and
  derived sample ID collisions.
- `tests/review/run.py`: container-backed stub routing for two phased samples and
  four assemblies, untrimmed short reads, raw/trimmed Hi-C-only samples, a Merqury
  database for untrimmed reads, supplied assemblies without long reads, and
  rejection when hifiasm emits no haplotypes.
- Python/JSON/YAML syntax checks, preserved upstream MPL-2.0 source notices,
  and `git diff --check`.

The new GitHub Actions workflow runs native and Docker FHR tests plus the routing
and initialization regressions on pushes to master, relevant pull requests and
manual dispatches.

## Limits

The phasing/read-routing tests use stubs with the real pinned tool containers.
They verify orchestration and output identity, not biological assembly quality.
A full real-data assembly, the complete upstream nf-test dataset suite,
R/Quarto report rendering, conda/Apptainer execution and a large-genome memory
benchmark were not run. The FHR converter reads complete files into memory;
large assemblies require an appropriate `fhr` process memory allocation.
